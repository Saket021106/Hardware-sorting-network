Why Hardware Sorting Networks?

Sorting is a foundational primitive in packet switching, database acceleration, signal processing (median and rank-order filters), and machine-learning inference (top-k selection). Software sorters branch on data, so their runtime varies and they serialize on a CPU. A sorting network is different: it is a fixed arrangement of compare-and-swap (CAS) elements whose structure never depends on the data. That makes it ideal for silicon, because every comparison at a given depth executes in parallel and timing is fully deterministic.

This project implements a bitonic sorting network in SystemVerilog. Its regular, recursive topology maps cleanly to hardware. It is parameterized so one source file scales across input counts and word widths, and it is pipelined so a new input vector can be accepted on every clock edge while earlier vectors are still moving through the network.

Deterministic

Fixed comparator topology gives constant latency with no data-dependent control flow.

Massively parallel

All CAS units within a stage operate simultaneously on independent pairs.

Streaming

Pipeline registers isolate stages, so throughput is one sorted vector per cycle.

Parameterization & Pipelining

The bitonic structure

A bitonic sorter of N = 2M inputs builds sorted sequences of doubling size. In merge phase p (1…M), sub-sequences of length 2p are merged through p sub-stages with comparator distances 2p-1, …, 2, 1. Whether a comparator sorts ascending or descending is decided by bit p of the element index. Total depth is:

M          = $clog2(NUM_INPUTS)
NUM_STAGES = M * (M + 1) / 2        // N=4 → 3 stages, N=8 → 6, N=16 → 10
CAS units  = (N / 2) * NUM_STAGES   // N=4 → 6 comparators

Figure: 4-input network as instantiated by the RTL. Stage 0 sorts pair (0,1) ascending and pair (2,3) descending to form a bitonic sequence; Stages 1 and 2 merge it into ascending order.

Parameterization

NUM_INPUTS and DATA_WIDTH drive everything: array dimensions, stage count via $clog2, and the topology itself. Nested generate loops over p, q and idx compute each comparator's stage index, distance j = 1 << q, and direction from idx & k, so no wiring is hand-written. NUM_INPUTS must be a power of two.

Pipelining

Instead of one long combinational path through every CAS level, each stage's outputs are captured in a register bank. The critical path collapses to a single comparator plus a mux, so clock frequency does not degrade as N grows. The trade-off is added latency and register area, in exchange for full streaming throughput.

From Concept to Verified RTL

  1. Concept & algorithm selection. Bitonic sort was chosen over odd-even merge sort for its uniform structure, since every stage contains exactly N/2 comparators, which simplifies generation logic.
  2. Mathematical mapping. Derive stage count M(M+1)/2, the flat stage index p(p-1)/2 + (p-1-q), comparator partner idx | j, and direction rule idx & k.
  3. Micro-architecture. Define the leaf CAS unit, a 2-D register array pipeline_regs[stage][lane], and a combinational wire array comb_wires between register banks.
  4. RTL coding. Implement cas_unit and the top-level sorting_network with generate blocks (see Section 04).
  5. Simulation. Drive a self-checking-style testbench with a 10 ns clock, dump a VCD, and inspect the per-CAS internals plus debug ports.
  6. Verification. Apply four directed vectors (scrambled, sorted, reversed, duplicates), confirm outputs are ascending permutations of the inputs, and confirm latency equals the predicted 4 clock edges.
  7. Scale-out. Change parameters (e.g. N = 8, 16; W = 16, 64) and re-run to prove the generator holds.

SystemVerilog Architecture

cas_unit #(WIDTH)

Purely combinational compare-and-swap. It asserts sel = (A > B) and routes the larger value to high and the smaller to low. Equal values keep their order, which makes it well-behaved with duplicates.

sorting_network #(N, W)

Top level. Registers inputs, generates all CAS stages, and registers every stage output. The out ports are wired directly from the last register bank.

Pipeline core

always_ff @(posedge clk) begin
  for (int n = 0; n < NUM_INPUTS; n++) pipeline_regs[0][n] <= in[n];
  for (int i = 0; i < NUM_STAGES; i++)
    for (int n = 0; n < NUM_INPUTS; n++)
      pipeline_regs[i+1][n] <= comb_wires[i][n];
end

Latency: NUM_STAGES + 1 clock cycles (input register + one per stage). For the default N = 4 this is 4 cycles = 40 ns.

What each signal group shows

debug_in0–3

Stimulus buses. They step at 50, 100, 150 and 200 ns, one new vector per phase.

Stage 0 CAS pairs

Inputs appear one clock after the stimulus (input register). Pair (0,1) puts the larger value on high (lane 1) and pair (2,3) reverses it, giving a bitonic sequence. For TC1: A/B = 0x59/0x0C → low 0x0C, high 0x59.

Stage 1 & 2 CAS units

Each stage is delayed by exactly one further clock. Stage 1 compares across distance 2 and stage 2 across distance 1, and their A/B values are the previous stage's high/low. This is the pipeline visibly propagating.

sel signals

Go high when A > B (a swap occurs). For sorted input TC2 the first-stage swaps are mostly inactive, and for reversed TC3 more comparators fire. Outputs stay correct either way.

debug_out0–3

Show X until the first data reaches the final bank, then become valid. Each result appears four clock edges after its input is captured, e.g. the 0x04, 0x0C, 0x2D, 0x59 output appears at 85 ns, the fourth clock edge (55, 65, 75, 85 ns) after the input changes at 50 ns.

Initial X region

Registers are unreset, so early internal values are unknown. This is expected. The testbench applies zeros for 50 ns to flush the pipeline before the first checked vector.

How this validates the design

Correctness: every output vector is ascending and a permutation of its input, including duplicates (TC4) and both best and worst case orderings. Pipelining: the staggered one-cycle offsets between stages confirm the register banks isolate each level. Determinism: latency is identical for all four vectors regardless of data. Generate correctness: the alternating direction in stage 0 and the ascending merges in stages 1–2 match the analytical bitonic schedule.

Formulas

Stages = M(M+1)/2. CAS units = (N/2) x stages. Latency = stages + 1 cycles. Register bits = (stages + 1) x N x W.

Growth

Depth grows as O(log² N) while comparators grow as O(N log² N). Register storage is the main cost of full pipelining.

To retarget

Instantiate with sorting_network #(.NUM_INPUTS(8), .DATA_WIDTH(16)) and widen the testbench arrays to match. NUM_INPUTS must be a power of two.

Hardware Implementation Notes

Critical path

Register, then a W-bit magnitude comparator, then a 2:1 mux per output, then the next register. Because every stage is registered, the path does not lengthen with N. Only the comparator width W affects it.

Area

Each CAS unit is one comparator plus two W-bit muxes. Flip-flop count is (stages + 1) x N x W, which usually dominates the area at large N.

Throughput and latency

Throughput is one sorted vector per clock at any N. Latency is stages + 1 cycles, so achievable sort rate equals the clock frequency the target device closes timing at.

Reset and X values

The registers have no reset, so early outputs are X until valid data flushes through. This is the red region in the waveform. Add a valid-bit shift register or a synchronous reset if downstream logic needs a clean start.

Possible extensions

Add a valid pipeline, signed-number compare, a sort-direction parameter, and a self-checking testbench with randomised vectors and a reference model.
